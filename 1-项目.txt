autoenc_function 是什么
  DreamWaQ 的核心架构是带 CeNet（Context Estimation Network，上下文估计网络） 的策略网络：
  观测历史（过去5帧obs）
          ↓
      CeNet (β-VAE 编码器)
          ↓
    latent code（隐向量）
          ↓
     拼接当前观测 → Actor → 动作

  CeNet 的任务：从机器人的历史感知序列里估计那些"不可直接测量"的信息——主要是线速度估计（sim-to-real 的核心障碍：真机无法直接读速度）和地形/环境隐变量。

  autoenc_loss 是这个 β-VAE 网络的训练损失，三项之和：

  autoenc_loss = MSELoss(估计速度, 真实速度)          # 速度估计精度
               + MSELoss(重建观测, 真实观测)           # 观测重建精度
               + β × KL散度                          # 隐变量正则化

  值越小 = 速度估计越准 + 重建越好 + 隐变量分布越规整。

mean_noise_std 是什么

  Policy 的动作分布是高斯分布 a ~ N(μ, σ²)，mean_noise_std 就是这个 σ（动作标准差），是一个可学习参数（初始值 1.0）。

  - 高 σ = 动作更随机，探索能力强
  - 低 σ = 动作更确定，policy 更保守
  - 正常训练：σ 应该从 1.0 逐渐降低并稳定在某个值（v9 稳定在 0.45，v6 稳定在 0.50）

训练稳定的标准
  在 PPO legged locomotion 训练中，"稳定"需要同时满足以下条件：
  ┌──────────────────┬─────────────────────────────┬──────────────────────────────────┐
  │       指标       │          稳定标准           │               说明               │
  ├──────────────────┼─────────────────────────────┼──────────────────────────────────┤
  │ terrain_level    │ 不单调下降，有上升趋势      │ 最核心指标，反映 policy 实际能力 │
  ├──────────────────┼─────────────────────────────┼──────────────────────────────────┤
  │ surrogate loss   │ 持续为负值                  │ 为正 → policy 更新方向错误       │
  ├──────────────────┼─────────────────────────────┼──────────────────────────────────┤
  │ noise_std        │ 稳定在 0.35~0.60 之间       │ 过低 → 过收敛；过高 → 发散       │
  ├──────────────────┼─────────────────────────────┼──────────────────────────────────┤
  │ learning_rate    │ 有波动，不长期卡在下限      │ 卡死在 1e-5 = LR 死锁            │
  ├──────────────────┼─────────────────────────────┼──────────────────────────────────┤
  │ mean_reward      │ 先升后平台，与 terrain 同步 │ 单独上升但 terrain 下降 = 假收敛 │
  ├──────────────────┼─────────────────────────────┼──────────────────────────────────┤
  │ value_function   │ 低且稳定（< 0.01）          │ 反映 critic 估计质量             │
  ├──────────────────┼─────────────────────────────┼──────────────────────────────────┤
  │ tracking_lin_vel │ > 0.5（对比 v9=0.863）      │ 速度追踪是行走能力的直接体现     │
  └──────────────────┴─────────────────────────────┴──────────────────────────────────┘

  满足以下 5 条 视为训练稳定：

  ┌────────────────┬───────────────────────────────────────────────────┐
  │      指标      │                     稳定标准                      │
  ├────────────────┼───────────────────────────────────────────────────┤
  │ surrogate loss │ 持续负值，无正值翻转                              │
  ├────────────────┼───────────────────────────────────────────────────┤
  │ noise_std      │ 不单调上升，稳定在某区间                          │
  ├────────────────┼───────────────────────────────────────────────────┤
  │ value_loss     │ 下降或平稳                                        │
  ├────────────────┼───────────────────────────────────────────────────┤
  │ mean_reward    │ 上升或稳定（不崩溃）                              │
  ├────────────────┼───────────────────────────────────────────────────┤
  │ LR             │ 不长期死在 1e-5（死锁），也不反复触达上限（爆炸） │
  └────────────────┴───────────────────────────────────────────────────┘

● entropy_coef 是 PPO 损失函数里的熵正则化系数。

    PPO 的总损失是：
    loss = surrogate_loss + value_loss_coef × value_loss - entropy_coef × entropy

  entropy（策略熵） 衡量动作分布的随机程度。对于高斯策略，entropy 与 noise_std 直接正相关——noise_std 越大，entropy 越高。

  entropy_coef 的作用：

  - entropy_coef > 0：损失函数里减去 entropy_coef × entropy，意味着熵越大 loss 越小。梯度下降时 PPO 会主动增大策略的随机性，鼓励探索，防止过早收敛到局部最优。
  - entropy_coef = 0：不对熵施加任何激励或惩罚，策略完全由 surrogate loss 和 value loss 驱动。
  - entropy_coef < 0（罕见）：主动惩罚高熵，强制策略收敛。

控制带宽对奖励函数的塑性和调优有什么影响？
  控制带宽对奖励函数塑性的影响

  什么是控制带宽

  控制带宽 ωn = √(k/J)，决定了关节对 policy 指令的响应速度：

  - 方案A（k=60）：ωn_thigh = 43.4 rad/s，响应周期 145ms，约是 policy 周期（20ms）的 7.2 倍
  - 方案B（k=28）：ωn_thigh = 28.4 rad/s，响应周期 221ms，约是 policy 周期的 11 倍

  ---
  带宽高（方案A，k=60）的影响

  对奖励的影响：

  1. action_rate 惩罚天然偏大：关节响应快，同等 policy 输出变化在关节上产生更大的实际角速度/力矩变化，action_rate 惩罚量天然比低带宽大。这是你日志里 boying 的 action_rate
  始终是 go1 的 2~4 倍的物理根源。
  2. 奖励函数需要更精细的抖动惩罚：高带宽放大了 policy 的每一次动作波动，奖励函数里抖动相关项（action_rate、smoothness）的比重需要更高，否则 policy 容易陷入震颤伪策略。
  3. 调参窗口窄：惩罚权重稍大就压死梯度，稍小又无法抑制震颤。你经历的几次崩溃都源于此。
  4. 正奖励相对被稀释：tracking 奖励的绝对量没变，但惩罚量翻倍，only_positive_rewards=True 把更多 reward clip 成 0，信号稀疏。

  对 sim-to-real 的影响：
  高刚度 k=60 在仿真里容易产生高频振荡，而真实电机的刚度通常随负载和温度变化，仿真与真实的差异更大。

  ---
  带宽低（方案B，k=28）的影响

  对奖励的影响：

  1. action_rate 惩罚自然压低：关节响应慢，policy 输出的高频分量被关节本身滤掉，不会直接传递到实际运动，action_rate 惩罚量接近 go1 水平。奖励函数无需特殊处理，直接复用 go1
  的权重即可。
  2. 奖励塑形空间更大：总惩罚量与 go1 接近，only_positive_rewards=True 的 clip 问题自然消失，奖励梯度信号更完整。
  3. 关节相当于低通滤波器：policy 可以输出粗糙的动作，关节自动平滑，减少了对 policy 精细度的要求，探索更容易收敛。
  4. 缺点：响应慢意味着精细步态调节能力下降，高速运动或快速方向变换时跟踪误差偏大。

  ---
  实际使用的方法：电机工作点比例缩放

  核心假设：GO1 的 PD 参数是经过实机验证的"好参数"，其与电机极限的比例关系是可以迁移的设计规律。

  k 的推导

  k_go1 = 28，T_stall_go1 = 33.5 N·m
  k_by  = k_go1 × (T_stall_by / T_stall_go1)
        = 28 × (60 / 33.5) = 50

  含义：k 控制"单位角度偏差产生多大力矩"，应与电机能输出的最大力矩成比例，否则同样的偏差误差在两台机器上的"力矩占比"不一样。

  这不是严格理论，只是"让力矩工作点比例相同"的工程直觉。

  d 的推导

  d_max = T_stall / v_max  （物理上限：最大速度下阻尼力矩不超过堵转力矩）
  d_go1 / d_max_go1 = 0.7 / (33.5/28) = 58.5%
  d_by  = 58.5% × (60/15.6) = 2.25

  含义：GO1 把 d 设在 d_max 的 58.5% 处，假设这个比例是合理的设计点，迁移到 boying。

  这也不是严格理论，d_max 这个概念本身是简化的——真实电机是力矩-速度曲线（非线性），不是简单的 T_stall/v_max。

  ---
  什么才是严格理论

  真正严格的 PD 参数设计应该基于以下之一：

  1. 二阶系统控制理论

  把关节+负载建模为：
  $$J\ddot{\theta} + d\dot{\theta} + k\theta = \tau_{ext}$$

  给定目标阻尼比 ζ 和自然频率 ωn：
  $$k = \omega_n^2 \cdot J, \quad d = 2\zeta\omega_n J$$

  需要知道：等效惯量 J、期望响应速度 ωn、期望阻尼比 ζ。

  2. 阻抗控制理论

  根据机器人与地面/负载的交互刚度，设计关节阻抗，使整腿的机械阻抗匹配地面接触特性。

  3. 频域设计（Bode/Nyquist）

  在离散时间下（考虑 decimation=4，policy 周期 20ms），设计 PD 使闭环系统有足够的相位裕量和增益裕量，避免离散化引入的延迟导致不稳定。

● 那就出现另外一个问题了，不同商家做的电机，同样的pd参数表现出来的效果一样吗？                                                                                                  
  不一样，差异很大。核心原因在于 PD 控制器作用在电机的输出侧，但电机本身的物理特性决定了同样的 PD 指令产生完全不同的实际响应。
  
  ---
  主要差异来源

  1. 力矩-速度曲线（最重要）

  电机的实际可用力矩随转速升高而下降：

  τ_actual = τ_stall × (1 - ω/ω_no_load)

  ┌──────────────┬───────────────────┬─────────────────────┐
  │              │     GO1 电机      │     Boying 电机     │
  ├──────────────┼───────────────────┼─────────────────────┤
  │ 堵转力矩     │ 33.5 N·m          │ 60 N·m（hip/thigh） │
  ├──────────────┼───────────────────┼─────────────────────┤
  │ 最大空载转速 │ 28 rad/s          │ 15.6 rad/s          │
  ├──────────────┼───────────────────┼─────────────────────┤
  │ 功率密度     │ 33.5×28/2 ≈ 469 W │ 60×15.6/2 ≈ 468 W   │
  └──────────────┴───────────────────┴─────────────────────┘

  两者功率密度几乎相同，但工作点完全不同。GO1 电机是高速低扭风格，Boying 是低速高扭风格。

  同样 k=26 的 PD 输出力矩指令，GO1 在高速运动时仍能较好执行，Boying 在高速时力矩余量更少，但低速大负载时响应更强。

  ---
  2. 减速比（Gear Ratio）

  URDF 里的 effort/velocity 是关节侧参数（已折算减速比后）。真正影响 PD 响应质量的是：

  - 减速比大（如 Boying 低速高扭型）：齿轮摩擦、间隙（backlash）更大，PD 的微分项 d 对实际速度的响应会被齿轮摩擦"吃掉"一部分，等效阻尼比实际上低于计算值
  - 减速比小（如 GO1 高速型）：响应更直接，d 的效果更准确

  结论：同样 d=0.64，GO1 实际阻尼效果可能比 Boying 更好，因为 Boying 的减速比更大，机械摩擦本身提供了一部分阻尼，但也引入了死区。

  ---
  3. 电机控制器（FOC vs 方波）

  URDF 里的 PD 是仿真中的理想 PD，真实电机还有底层电流环/速度环：

  - GO1 用的是 Unitree 自研的 FOC 控制器，底层 1kHz 电流环，PD 指令传递带宽高
  - Boying 的电机品牌未知，如果底层控制器带宽低（如 500Hz），高频抖动会被底层截断，等效于给 d 项加了一个低通滤波器

  在仿真里这个差异不存在——仿真里 PD 是直接计算力矩，没有底层控制器的带宽限制，所以 sim-to-real 时 Boying 可能比 GO1 差距更大。

  ---
  4. 仿真中的简化（对训练的直接影响）

  legged_gym 里的 PD 实现是：

  torques = p_gains * (target - dof_pos) - d_gains * dof_vel

  这是理想 PD，没有：
  - 电机饱和（力矩被 torque_limits clip，但中间没有力矩-速度曲线）
  - 减速比摩擦
  - 底层控制器延迟
  
  所以在仿真里，同样的 k/d 对两台机器人确实产生"相同比例"的动态响应（这也是我们用惯量匹配方法的前提成立的地方）。但部署到真机时，差异会显现。

  ---
  对现在训练的影响

  在仿真训练阶段，用二阶系统推导的 k=26, d=0.64 是合理的——两台机器人的仿真响应特性对齐了。

  但如果之后要 sim-to-real，需要考虑：
  1. Boying 减速比大 → 真机阻尼比仿真更大，可能需要适当降低 d
  2. Boying 底层控制器带宽未知 → 需要实测调整

  这也是为什么 legged_gym 里有 randomize_Kp_factor 和 randomize_Kd_factor 域随机化的原因——用 [0.9, 1.1] 的随机扰动来模拟真机 PD 执行的不确定性。
