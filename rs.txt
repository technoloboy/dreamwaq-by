  Method B 理论值在 Boying 上失效，不能直接套用。

### v8 — Resume from v6（Jul23_14-45-26_, 18000 iters）
变更：无奖励变更，从 Jul22_19-00-58_ step 16200 恢复，PPO 仍使用 adaptive LR

结果：灾难性退化
  terrain 0-9k 正常（峰值 3.88 @step 8550），之后单调下滑至 2.82（step 18000）
  mean_reward 从 18.8 跌至 0.8（跌幅 96%）；ep_length 从 986 跌至 167
  surrogate loss step 9k 后转正（+0.009），policy 更新方向完全错误

  根本原因：adaptive LR + checkpoint resume 的致命组合
    从已收敛的 checkpoint 恢复时 KL 极低（接近 0），连续触发 "kl < desired_kl/2"
    → lr × 1.5 反复执行，约 40 步内从 5e-4 飙至上限 1e-2
    → 1e-2 大步长破坏已收敛 policy，KL 爆炸
    → lr 被压死到 1e-5，surrogate 转正，无法自愈
    step 8510 第一次脉冲（45 iters），step 8670-8906 第二次脉冲（237 iters，全程 1e-2）

  v6 从头训练时 LR 从未超过 3.84e-4，此次 resume 才触发爆炸。
  与奖励函数和 PD 参数无关，是优化器配置问题。

  修复：在 boying_config.py 中新增：
    schedule = 'fixed'
    learning_rate = 1e-4
  已应用到代码（BoyingRoughCfgPPO.algorithm）。

  与 v8 的 adaptive LR 爆炸模式相同：
    step 7600 surrogate 接近 0 → KL 降低 → adaptive LR 开始上冲

    阈值调整对抬腿质量有一定效果，但被崩溃掩盖

结论：
  - feet_air_time_threshold=0.3 是有效的，但崩溃原因与 threshold 无关
  - adaptive LR 在 training 过程中同样会爆炸，不只是 resume 时
  - 后续训练建议统一改为 fixed LR=1e-4（见修复方案），或使用 desired_kl 更保守的值

### v11 — Fixed LR=1e-4 从头训练（Jul24_23-43-24_, 888 iters）✗ 冷启动失败
变更（相对 v10）：
  schedule      'adaptive' → 'fixed'
  learning_rate 1e-3 → 1e-4

结果：灾难性冷启动失败
  terrain step 0 起单调下降，step 888 时跌至 0.0000（课程底部）
  mean_reward 全程为负（-5 ~ +5，全期基本负值）
  noise_std 全程 0.92~0.95，从未有效下降（v6 同期已降至 0.87 以下）

根本原因：fixed LR=1e-4 与从头训练不兼容（冷启动问题）
  初始策略是完全随机的（noise_std=1.0），奖励为负，地形课程快速下降。
  fixed LR=1e-4 步长极小，每步 policy 更新幅度太小，无法快速逃离负奖励区。
  对比 v6（adaptive LR）早期行为：
    v6 在 step 3-7 内 LR 从 4.4e-4 飙至 5e-3，大步长快速摆脱随机初始化
    v11 全程卡在 1e-4，noise_std @step 40 仍 0.93（v6 同期已至 0.70）
    v6 @step 48 出现第一个正 reward；v11 @step 888 仍未见正 reward

  结论：
  - adaptive LR 在早期（0~300步）是必要的：初始 KL 大 → LR 自动上冲到 1e-3~5e-3
    提供足够大的梯度步让策略快速建立基本行走能力
  - fixed LR=1e-4 只适合 resume 已收敛策略：此时 KL 本已很小，1e-4 足以
  - "adaptive LR 在从头训练时会爆炸"的结论（v10）是有条件的：
    爆炸发生在 step 7600 策略趋于收敛时，而非早期探索阶段
  - 正确方案：warm-up 阶段用 adaptive，收敛时手动或自动切换 fixed

修复方案（v12）：
  先用 adaptive LR=1e-3 训练至 terrain 稳定（约 3000-5000步）
  在 surrogate 接近 0 或 terrain 开始不动时，改为 fixed LR=1e-4 resume
  或：设置更保守的 adaptive LR 上限（max_lr 降至 1e-3，避免 1e-2 峰值）

  需要同时调整 entropy_coef（降低探索激励）和适当放宽 max_learning_rate。

    → terrain 无突破，卡在与 v13 相同的平台

  LR（新问题 - LR 死锁）：
    LR=1e-5（下限）占比: 52.7%；LR>1e-4 仅占 1.4%
    mean=2.05e-5（极低，基本是死的）
    surrogate 全程正值（mean=+0.001，正值占 55.1%）
    → KL 持续 > 2×desired_kl → adaptive LR 反复被压到 1e-5

LR 死锁根本原因：
  从 v13 step 8000（noise_std=0.84）的半发散状态 resume，
  policy 参数处于"高熵但低奖励"的状态，advantage 函数估计误差大。
  entropy_coef 从 0.01 骤降至 0.001 后，policy 快速向低熵收缩，
  每步参数变化幅度超过 clip 范围 → ratio>1 → surrogate 为正 → KL 爆炸
  → adaptive LR 反复被压死在 1e-5 → policy 更新停滞 → terrain 无法进步

结论：
  ✓ entropy_coef=0.001 对 noise_std 的压制效果极强（0.84→0.25，优于 v9）
  ✓ action_rate/smoothness 历史最佳，说明动作平滑性得到根本改善
  ✗ LR 死锁：surrogate 正值 + KL 过大导致 adaptive LR 失效
  ✗ terrain 未能突破 4.0-4.1 平台，policy 学习基本停滞
  ✗ base_height 异常：躯干高度偏差 0.118m（v9/GO1 仅 0.042m，相差 2.8x）
     base_height scale=-1.0（GO1默认）对台阶地形 Boying 过强
     v15 改为 -0.5，给机器人更多空间自然调整躯干高度应对台阶
  根因：从半发散状态 resume 时 entropy 骤降 → KL 过大 → LR 死锁
  解决方案：从头训练（避免 resume 的状态不匹配），或改用 fixed LR
